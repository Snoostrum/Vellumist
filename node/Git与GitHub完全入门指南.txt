================================================================================
一、Git 和 GitHub 的关系
================================================================================

Git  = 版本控制工具，装在你电脑上，命令行操作。
GitHub = 网站，托管 Git 仓库的远程服务器。

类比：Git 是「相机」，GitHub 是「相册网站」。
你用相机拍照（commit），然后上传到相册网站（push）给别人看。


================================================================================
二、Git 核心概念：三个区域 + 一个远程
================================================================================

工作目录 ──git add──▶ 暂存区 ──git commit──▶ 本地仓库 ──git push──▶ 远程仓库
(Working Dir)        (Staging)            (Local Repo)        (Remote)

┌────────────┬─────────────────────────┬──────────────────────────┐
│ 区域       │ 说明                    │ 类比                     │
├────────────┼─────────────────────────┼──────────────────────────┤
│ 工作目录   │ 你正在编辑的文件         │ 桌上的草稿纸             │
│ 暂存区     │ 标记为「准备提交」的文件  │ 放进信封准备寄出         │
│ 本地仓库   │ 已提交的版本历史         │ 抽屉里存档的旧稿         │
│ 远程仓库   │ GitHub 上的版本          │ 云端备份                 │
└────────────┴─────────────────────────┴──────────────────────────┘

关键理解：git add 和 git commit 是两步，因为你可以选择性地提交——
改了 10 个文件但只想提交其中 3 个，完全 OK。


================================================================================
三、基础操作（必会）
================================================================================

3.1 初始化 / 克隆
──────────────────────────────────────────────────────────────────────

# 新建一个仓库
git init

# 从 GitHub 克隆别人的仓库
git clone https://github.com/user/repo.git

# 用 SSH 克隆（配置好密钥后推荐）
git clone git@github.com:用户名/仓库名.git


3.2 日常提交流程
──────────────────────────────────────────────────────────────────────

# 查看改了哪些文件
git status

# 查看具体改了什么内容
git diff

# 把文件加入暂存区
git add 文件名           # 单个文件
git add .                # 当前目录所有修改
git add -A               # 全部修改（包括删除）

# 提交到本地仓库
git commit -m "修复了登录页面的空指针异常"

# 推送到 GitHub
git push origin main

# 从 GitHub 拉取最新代码
git pull origin main


3.3 查看历史
──────────────────────────────────────────────────────────────────────

git log                   # 完整历史
git log --oneline         # 一行一条，清爽
git log --graph --all     # 图形化分支结构
git show <commit-hash>    # 查看某次提交的具体改动


================================================================================
四、分支（Branch）—— Git 最强大的功能
================================================================================

4.1 为什么需要分支？
──────────────────────────────────────────────────────────────────────
你正在开发「用户关注」功能，突然线上出了 bug 要紧急修复。
如果没有分支，半成品代码和 bug 修复混在一起，没法单独上线。

main:     ●──●──●──────────────────●──  (稳定版本)
                \
feature/follow:  ●──●──●──          (开发中的关注功能)
                         \
hotfix:                   ●──       (紧急修复)


4.2 分支操作
──────────────────────────────────────────────────────────────────────

# 查看所有分支
git branch -a

# 创建分支
git branch feature/login

# 切换分支
git checkout feature/login

# 创建并切换（一步到位）
git checkout -b feature/login

# 现代写法（Git 2.23+）
git switch -c feature/login    # 创建并切换
git switch main                # 切换已有分支

# 删除分支
git branch -d feature/login    # 安全删除（已合并的）
git branch -D feature/login    # 强制删除


4.3 合并分支
──────────────────────────────────────────────────────────────────────

# 把 feature/login 合并到 main
git checkout main
git merge feature/login


4.4 合并冲突——每个新手都会遇到
──────────────────────────────────────────────────────────────────────
当两个分支改了同一文件的同一行时，Git 不知道听谁的，就会产生冲突：

冲突标记长这样：
    <<<<<<< HEAD
        private String username;
    =======
        private String nickname;
    >>>>>>> feature/login

解决步骤：
  1. 手动编辑文件，删掉 <<<<<<<  =======  >>>>>>> 标记，保留正确的代码
  2. git add 文件名
  3. git commit（不需要 -m，Git 会生成 merge commit 信息）


================================================================================
五、GitHub 协作流程
================================================================================

5.1 连接 GitHub
──────────────────────────────────────────────────────────────────────

# 关联远程仓库
git remote add origin https://github.com/你的用户名/仓库名.git

# 查看远程仓库
git remote -v

# 推送到 GitHub（首次需要 -u 建立追踪）
git push -u origin main


5.2 SSH 密钥配置（推荐，配一次永久免密）
──────────────────────────────────────────────────────────────────────

# 1. 生成 SSH 密钥
ssh-keygen -t ed25519 -C "你的邮箱@example.com"
# 一路回车即可

# 2. 启动 ssh-agent 并添加密钥
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# 3. 查看公钥（复制全部内容）
cat ~/.ssh/id_ed25519.pub

# 4. 打开 https://github.com/settings/keys
#    点击 New SSH Key → 粘贴公钥 → Add SSH Key

# 5. 测试连接
ssh -T git@github.com
# 看到 "Hi 你的用户名! You've successfully authenticated" 就成功了

# 6. 以后 clone 用 SSH 地址
git clone git@github.com:用户名/仓库名.git


5.3 Pull Request（PR）—— 协作核心
──────────────────────────────────────────────────────────────────────
PR 不是 Git 的功能，是 GitHub 的功能。流程：

  1. Fork 别人的仓库（或在自己的仓库创建分支）
  2. Clone 到本地
  3. 修改 + commit + push 到你的分支
  4. 在 GitHub 网页上点击 New Pull Request
  5. 写清楚你改了什么、为什么这么改
  6. 等待代码审查（Code Review）和合并

实际操作：
  git clone git@github.com:我的用户名/repo.git
  cd repo
  git checkout -b fix-login-bug
  # ... 修改代码 ...
  git add .
  git commit -m "修复登录空指针: 增加 null 检查"
  git push origin fix-login-bug
  # 然后去 GitHub 页面创建 PR


================================================================================
六、常用进阶操作
================================================================================

6.1 撤销操作
──────────────────────────────────────────────────────────────────────

# 撤销工作区的修改（回到上次 commit 的状态）
git checkout -- 文件名
git restore 文件名                 # 新版写法

# 撤销 git add（从暂存区移除）
git reset HEAD 文件名
git restore --staged 文件名        # 新版写法

# 撤销最近一次 commit（保留修改）
git reset --soft HEAD~1

# 撤销最近一次 commit（连修改一起丢！慎用）
git reset --hard HEAD~1

# 创建一个新 commit 来「反向操作」某次提交（安全）
git revert <commit-hash>


6.2 暂存工作现场（stash）
──────────────────────────────────────────────────────────────────────

# 正在开发中，突然要切分支修 bug，但又不想 commit 半成品
git stash                    # 暂存当前修改

# ... 去修 bug 切回来 ...

git stash pop                # 恢复刚才暂存的修改
git stash list               # 查看所有暂存
git stash drop               # 删除最近一次暂存


6.3 变基（rebase）—— 让历史更干净
──────────────────────────────────────────────────────────────────────

# 把 feature 分支的 commit 接到 main 最新位置
git checkout feature
git rebase main

# 交互式 rebase —— 合并多个 commit
git rebase -i HEAD~3          # 合并最近 3 个 commit

merge vs rebase：
  merge  → 保留真实历史，但分支图复杂，新手友好
  rebase → 历史干净线性，但改写了历史，新手建议先用 merge


6.4 .gitignore —— 忽略不该提交的文件
──────────────────────────────────────────────────────────────────────
不应该提交到 Git 的：编译产物、IDE 配置、密码文件。

.gitignore 文件内容示例：
  target/                        # Maven/Gradle 编译输出
  *.class                        # Java 字节码
  .idea/                         # IntelliJ IDEA 配置
  *.log                          # 日志文件
  application-local.properties   # 本地配置（含密码）
  node_modules/                  # npm 依赖
  .env                           # 环境变量

模板生成：https://www.toptal.com/developers/gitignore

七、实战建议
================================================================================

7.1 Commit 信息规范
──────────────────────────────────────────────────────────────────────

好的 commit message：
  feat: 新增用户关注功能
  fix: 修复登录时 NPE 异常
  refactor: 提取 JWT 验证逻辑到工具类

不好的 commit message：
  改了点东西
  fix bug

常用前缀：
  feat     → 新功能
  fix      → 修 bug
  refactor → 重构（不改功能）
  docs     → 文档
  test     → 测试
  chore    → 杂活（改配置等）


7.2 推荐日常开发节奏
──────────────────────────────────────────────────────────────────────

# 每天开始前
git pull origin main

# 创建功能分支
git checkout -b feat/xxx

# 写一会儿就提交（小步提交！不要攒一大坨）
git add .
git commit -m "feat: xxx — 完成数据层"

# 继续写，继续提交
git add .
git commit -m "feat: xxx — 完成业务逻辑"

# 推送到 GitHub（随时备份！）
git push origin feat/xxx

# 功能完成 → 创建 PR → 代码审查 → 合并 → 删除分支

九、GitHub 终端登录（三种方式）
================================================================================

方式一：GitHub CLI（gh）—— 最推荐，功能最全
──────────────────────────────────────────────────────────────────────

安装：
  winget install GitHub.cli

登录：
  gh auth login

按提示选择：
  1. GitHub.com
  2. SSH（推荐）
  3. Yes（让它自动生成并上传 SSH 公钥）
  4. Login with a web browser（浏览器弹出后点授权）

验证：
  gh auth status

gh 常用命令：
  gh repo create              # 在 GitHub 上创建仓库
  gh repo clone 用户名/仓库名  # 克隆仓库
  gh pr create                # 创建 Pull Request
  gh issue list               # 查看 Issues


方式二：手动配置 SSH 密钥（只管 push/pull/clone）
──────────────────────────────────────────────────────────────────────

  ssh-keygen -t ed25519 -C "你的邮箱@example.com"
  eval "$(ssh-agent -s)"
  ssh-add ~/.ssh/id_ed25519
  cat ~/.ssh/id_ed25519.pub          # 复制输出内容
  # 去 https://github.com/settings/keys → New SSH Key → 粘贴 → 保存
  ssh -T git@github.com              # 测试


方式三：HTTPS + Personal Access Token（特殊场景）
──────────────────────────────────────────────────────────────────────

  # 不推荐日常使用，每次 push 都要输 token
  # 1. 打开 https://github.com/settings/tokens
  # 2. Generate new token (classic)
  # 3. 勾选 repo 权限
  # 4. 生成后复制保存（只显示一次！）
  # 5. push 时，用户名填 GitHub 用户名，密码填这个 token


┌──────────────┬──────────────────────────────┬──────────────┐
│ 方式         │ 适合场景                      │ 复杂度       │
├──────────────┼──────────────────────────────┼──────────────┤
│ gh auth login│ 管理 Issue、PR、仓库          │ 最简单       │
│ SSH 密钥     │ 只管 push/pull/clone          │ 配一次永久用 │
│ HTTPS+Token  │ 特定网络环境                  │ 每次输 token │
└──────────────┴──────────────────────────────┴──────────────┘

十、常见问题排查
================================================================================

Q: fatal: this operation must be run in a work tree
A: 当前目录不是 Git 仓库。解决方法：
   1. git init（把当前目录变成仓库）
   2. 或者 cd 到你 clone 下来的项目目录里
   3. 检查：git status 是否正常

Q: fatal: not a git repository
A: 同上，当前目录没有 .git 文件夹。

Q: 推送被拒绝（rejected）
A: 远程有新提交你还没拉取。
   git pull origin main
   # 解决可能的冲突后再 push
   git push origin main

Q: 合并冲突怎么办？
A: 1. 打开冲突文件，删掉 <<<<<<< ======= >>>>>>> 标记
   2. git add 文件名
   3. git commit

Q: 不小心提交了不该提交的文件？
A: git reset --soft HEAD~1   # 撤销提交但保留修改
   然后修改 .gitignore，重新 add 和 commit

Q: 已经用 HTTPS clone 了，想换成 SSH？
A: git remote set-url origin git@github.com:用户名/仓库名.git

记住：你不需要背下所有命令。
git status 是最常用的，随时随地用它看看当前状态。
80% 的场景只需要：status → add → commit → push/pull 这几步。
